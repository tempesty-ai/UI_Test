## 에이전트 판정 신뢰도 검증 ⭐

에이전트가 낸 판정을 그대로 믿지 않고 사람이 재검토해 신뢰도를 측정합니다.
아래는 2026-05-06 실행분(이슈 4건)에 대한 재검토 결과입니다.

| 이슈 | 에이전트 판정 | 재검토 결과 |
|---|---|---|
| ISSUE-001 이미지 미렌더링 | P2 Major | 유효 — 375px·768px 스크린샷에서 재현 확인 |
| ISSUE-002 가격 텍스트 잘림 | P3 Minor | **False Positive** — 스크린샷에 $14.15 정상 표시 |
| ISSUE-003 콘솔 에러 | P2 Major | 검증 불가 — 콘솔 로그 미보존 |
| ISSUE-004 카트 아이콘 | P3 Minor | 결함 아님 — 표준 반응형 패턴, 개선 제안으로 재분류 |

**그대로 채택 가능: 4건 중 1건**
(False Negative는 PASS 항목 재실행이 필요해 미측정)

### 여기서 얻은 것

ISSUE-002는 에이전트가 **자신이 촬영한 스크린샷과 모순되는 판정**을 낸 사례입니다.
근거 데이터가 있어도 판정 단계에서 환각이 발생할 수 있음을 보여줍니다.

ISSUE-004는 의도된 설계를 결함으로 분류한 사례로,
에이전트에 도메인 판단 기준을 얼마나 구체적으로 주느냐가 정확도를 좌우함을 시사합니다.

ISSUE-003은 판정보다 **증거 보존 설계**의 문제였습니다.
콘솔 로그를 리포트에 함께 저장하지 않으면 사후 검증이 불가능합니다.

### 개선 과제

1. 콘솔 로그·네트워크 로그를 이슈 폴더에 함께 보존 (검증 가능성 확보)
2. "의도된 설계 vs 결함" 판단 기준을 SKILL.md에 명시
3. 스크린샷 근거와 판정문을 대조하는 2차 검증 단계 추가
